Frequently Asked Questions

What server log formats can LogLens parse and ingest?
LogLens is engineered to ingest the standard Apache / Nginx Combined Log Format. It automatically parses client IP addresses, ISO/Apache date-time stamps, HTTP request verbs (GET, POST, etc.), URI endpoints, and 3-digit numeric HTTP status codes using high-speed Java regex streams.
How does LogLens classify log levels (INFO, WARN, ERROR)?
Log severity is mapped systematically according to HTTP response status codes:
  • INFO: All successful requests and redirects (HTTP status codes 200–399).
  • WARN: Client-side errors such as 404 Not Found and 403 Forbidden (HTTP 400–499).
  • ERROR: Internal server failures and gateway timeouts (HTTP 500–599).
Where is log data stored, and does it persist across restarts?
Data is persisted to an embedded file-backed H2 relational database located at ./data/logdb.mv.db. When the Spring Boot application shuts down or restarts, all loaded log records and submitted support tickets remain completely intact on disk.
How can I query or inspect the embedded H2 database directly?
Spring Boot H2 Console is enabled. While the server is running, navigate to http://localhost:8080/h2-console. Connect using JDBC URL: jdbc:h2:file:./data/logdb and username: sa (with an empty password) to run custom SQL queries on the LOG_ENTRY and SUPPORT_TICKET tables.
Can I load a different log file or increase the line limit?
Yes. You can point the file path constant in com.example.loganalyzer.LogLoader to any valid access log file and modify MAX_LINES (currently defaulting to 10,000 lines). The loader automatically inspects existing records to avoid duplicate inserts.
How are support tickets submitted through this page handled?
When you submit the contact form, your browser issues a JSON request via fetch() to the POST /api/tickets endpoint. Spring Boot's TicketController validates the data and stores it in the database using SupportTicketRepository with an automatic creation timestamp.
