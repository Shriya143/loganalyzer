About LogLens

Learn about our mission, technology architecture, and how real-world server logs are parsed and analyzed.

What is LogLens? Architecture Overview

LogLens is a full-stack log observability and analytics platform designed to solve one of the most critical challenges in systems engineering: converting massive, messy web server access logs into actionable operational intelligence.

Modern applications generate millions of HTTP access lines every day. When unexpected downtime, broken routing, or malicious probes occur, combing through flat log files manually is slow and error-prone. LogLens ingests raw logs, normalizes their schemas, classifies them by severity, and exposes them through lightning-fast REST endpoints and interactive visual dashboards.

Automated Severity Classification
HTTP 2xx & 3xx responses are categorized as INFO, client-side 4xx errors (such as 404 Not Found and 403 Forbidden) are grouped as WARN, and 5xx internal server faults (such as 500 and 502) are flagged as ERROR.

Technology Stack & Tools

Built on modern, industry-standard technologies to ensure high throughput, reliability, and clean separation of concerns.

Core Language

Java 21

High-performance, strongly-typed execution environment powering our batch regex log parser, multi-threaded request processing, and database transactions.

Backend Framework

Spring Boot

Modern microservice foundation utilizing Spring Web MVC for clean REST APIs (/api/levels, /api/top-errors, /api/logs, /api/tickets) and Spring Data JPA for data access.

Persistence Engine

H2 Database

Embedded, disk-backed SQL relational database (jdbc:h2:file:./data/logdb). Delivers sub-millisecond query execution, zero external server overhead, and integrated H2 Console support.

Data Visualization

Chart.js

Client-side HTML5 canvas visualization library providing reactive, responsive pie and horizontal bar charts with interactive hover tooltips and dynamic color theming.

Data Source: Kaggle Apache Access Logs Dataset

The analytics engine is evaluated against real-world production server traffic sourced from the Kaggle Apache Web Server Access Log dataset.

10.128.2.1 - - [26/Jan/2019:20:00:15 +0330] "GET /image/product/12 HTTP/1.1" 200 12845

During application startup, the LogLoader component reads the log file via a buffered stream and applies an optimized regular expression pattern to parse:

  • Timestamp: Converted from Apache format (dd/MMM/yyyy:HH:mm:ss) to standard ISO SQL format (yyyy-MM-dd HH:mm:ss).
  • HTTP Method & Endpoint: Extracted and normalized (e.g., GET /image) for clean aggregation.
  • Response Code: Parsed to compute both the severity level and error message representation.
  • Batch Persistence: Records are saved into the LOG_ENTRY table with automated duplicate checking.
